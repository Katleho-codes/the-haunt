## 3. Brief Must-Haves unmet because of the local-first decision

Not defects, but they must not be claimed:

- Server-backed storage, authentication, per-user server ownership.
- A reminder path that works while the app is closed. Reminders are in-app only.
- Publicly deployed demo, judge path (nothing deployed in the repo).
- Real data deletion of server data (n/a); local deletion exists but see M-1.
- Image/PDF/voice capture, AI extraction (Should/Could Have; the UI says "Voice soon", "Files soon").
- Timezone and locale preferences in the UI (M-7), default reminder offsets exist.
- Edit scopes "this occurrence" / "this and future", pause series, end-date entry.
- Monthly summary: only a 7-day total exists; no month view of recurring amounts.

Public wording check: README, Settings "Prototype notice" (`components/haunt-app.tsx` SettingsView) and the notification centre all state local, in-app, not AI. I found no wording that implies a server, push, email or AI. Good.

## 4. Verified defects

### H-1 Archived commitments vanish and cannot be restored
- **Evidence:** `components/haunt-app.tsx:238-241` builds list sources from `completed`, `recurring` or `active` only. `archiveItem` at `:354-357` toasts "Archived. The history is kept." Playwright probe: archiving "Dentist appointment" dropped rows 6 to 5 and the item appeared in The Hall, Clocktower and Crypt checks: none. Restore is only offered when `completed` (row menu) so even a visible archived row would not restore.
- **Why it matters:** user data appears deleted. The toast claims history is kept. Only delete-all or export reveals it. Violates honest-state principle.
- **Smallest safe fix:** add an "Archived" filter or section (Archive view toggle) listing `status === "archived"` rows with a Restore action (`restoreCommitment` already handles it). Until then, remove the Archive menu item.

### H-2 Toggle switches have no accessible name
- **Evidence:** `SettingToggle` renders `<button role="switch" aria-checked>` with an empty `<span/>` child and no label (`components/haunt-app.tsx`, `SettingToggle`, near the end of the file). Probe: both switches report `<none>` for name. e2e selects them by `[role="switch"]` index, so it cannot catch this.
- **Why it matters:** screen-reader users cannot tell what the ambience and interaction-sound switches do. Sound is the product's most sensitive setting.
- **Fix:** add `aria-label={title}` (or `aria-labelledby` the visible `<strong>`) and `aria-describedby` for the description. Add an e2e assertion `getByRole("switch", { name: "Ambient atmosphere" })`.

### H-3 No LICENSE file
- **Evidence:** `git ls-files` has no LICENSE; repo root listing confirms. `.kiro/steering/competition.md` and `release-and-demo` requirement 1 require a visible open-source licence.
- **Why it matters:** submission eligibility.
- **Fix:** owner picks a licence (e.g. MIT or Apache-2.0), add `LICENSE`, mention it in README. This needs an owner decision; I did not pick one.

### M-1 Delete-all leaves backups of user data
- **Evidence:** `lib/storage/local-storage-repository.ts:157-161` removes only the store key and the two legacy keys. `init` writes raw corrupt copies to `the-haunt.corrupt.<user>.<iso>` (`:44-47`, `:60-63`). Probe: after `deleteAll` the corrupt key remained. The e2e delete-all step (`e2e/smoke.mjs`, last steps) only checks `the-haunt.store*` keys, and would pass either way.
- **Why it matters:** the UI says "Delete every commitment and setting stored in this browser". Raw copies, possibly containing payment details, survive. Contradicts the security steering (deletion path).
- **Fix:** have `deleteAll` enumerate keys with the `the-haunt.` prefix via `storage.length/key(i)` (extend `KeyValueStorage`) and remove all. Add a regression test and extend the e2e step.

### M-2 Export is incomplete; no import
- **Evidence:** `exportData` (`haunt-app.tsx:398-403`) writes `{version, exportedAt, commitments, settings}`. Occurrences (completion history) and reminders are omitted. Probe confirmed keys: `version,exportedAt,commitments,settings`. No import path exists.
- **Why it matters:** "Export my data" is advertised as a backup (README). Restoring is impossible and history is lost. Recurring series restored from this file would have no history.
- **Fix:** include `occurrences` and `reminders` (or state exactly what is exported), and say in the UI/README that import does not exist. Import must validate with `storedDataSchema` if added.

### M-3 False amount from unit words
- **Evidence:** `lib/capture/extract.ts:40` accepts `pounds?`, `dollars?`, `euros?` after a number. Probe: "Buy 2 pounds of sugar on 25 Nov" gives `amountMinor 200, currency GBP` with no review note (confidence 0.9). Only `$` and "dollars" carry an assumption note.
- **Why it matters:** a wrong amount appears in the form and in totals without a CHECK THIS marker. It does need confirmation, but the marker is the product's safety net.
- **Fix:** drop the word currencies, or flag all non-symbol/non-code markers as assumed. Add regression tests.

### M-4 Time of day silently dropped, date text left in title
- **Evidence:** no time extractor in `extract.ts`. Probe: "Dentist 25 November at 14:30" yields title "Dentist 25 November", no time, no note. `PRODUCT-STATUS.md` admits times are not handled, the UI does not tell the user.
- **Fix:** if `\d{1,2}[:h]\d{2}` or "at 5pm" is present, add a `general` review note "A time was found and ignored; times are not read yet." Add `on`/month cut cue to the title cutter so "25 November" is not kept.

### M-5 Tiny text
- **Evidence:** `app/globals.css` uses 7, 8, 9, 10px for labels, metadata, due dates, notes (e.g. `:42`, `:54`, `:116`, `:148`, `:152-153`, `:181` is 7px). Probe of rendered text: sizes 6px (3 nodes), 7px (6), 8px (34), 9px (5), 10px (5); the main title is 12px.
- **Why it matters:** contrast tooling passes, but legibility on mobile and for low vision is poor. The brief says "Text contrast must remain readable"; steering says usability over atmosphere.
- **Fix:** set a floor of 11px for mono labels and 12px for body/meta; use `rem`. Re-run the screenshot script.

### M-6 Data loss paths
- **Evidence:** (a) no `storage` event listener (grep found none); every effect writes whole arrays with `replaceAll` (`haunt-app.tsx:150-163`), so two tabs overwrite each other, last writer wins. (b) `write()` (`local-storage-repository.ts:178-181`) has no try/catch; `void repository.replaceAll(...)` discards rejections, so on quota error or a Zod failure the UI shows success and nothing persists. I did not trigger a quota error in a browser.
- **Fix:** catch in the effect and show a banner "Could not save"; listen for `storage` and reload or warn on foreign changes. Optional: a `updatedAt` check before writing.

### M-7 No timezone/locale preference
- **Evidence:** `SettingsView` has no timezone or locale control. `settings.timezone` is whatever the browser reported on first creation (`local-storage-repository.ts:175`). `today` derives from `settings.timezone` (`haunt-app.tsx:207`), so after travel or a bad first value, "today" and reminder time use the old zone. Brief 5.9 and the localisation section require user-editable timezone/locale.
- **Fix:** add timezone and locale selects in the Keeper's Room (validated by `timeZoneSchema`); reconcile reminders is already timezone-aware.

### M-8 Overdue recurring items
- **Evidence:** `completeOccurrence` advances to the next date after the *current* due date (`lib/recurrence/series.ts:48`). Probe: monthly rule on 31 Jan completed on 13 Nov gives next due 2026-02-28, still ten months overdue. Each click records an occurrence "completed" at the click time.
- **Why it matters:** inflates The Crypt with fake completions, and the next due stays "Restless".
- **Fix:** offer "Skip to the next upcoming date" (use `nextOccurrenceAfter(rule, start, today)` while recording one completion), or at least tell the user. Needs a product decision.

### L-1 Search shortcut is shown but absent
- `haunt-app.tsx:446` renders `<kbd>⌘ K</kbd>`; no key handler exists (grep for `metaKey|ctrlKey` found nothing; probe: Ctrl+K opened nothing). **Fix:** implement or remove the hint.

### L-2 Unlabelled controls
- Search popover input and its close button have no label (`:454`); toolbar search input has only a placeholder (`:512`); display-currency select has no label (SettingsView); row menu buttons lack `aria-haspopup/aria-expanded`, no Escape handling, and the full-screen `menu-dismiss` button is a tab stop; completion control reads "Mark complete" without naming the item. The modal's amount `<label>` wraps two controls (select and input). Reminder chips in the modal lack `aria-pressed` (the settings ones have it).
- **Fix:** add `aria-label`s; give the complete button `aria-label={`Mark ${item.title} complete`}`; add `aria-expanded` and Escape to the row menu.

### L-3 Edit-then-complete dead end
- Probe: complete 31 Jan, edit due date back to 31 Jan, complete again returns "This occurrence is already completed" (`series.ts:42-43`). The user can escape by changing the date again, but the message does not say so. **Fix:** clearer message, or remove the history record when a user explicitly re-dates onto a completed date.

### L-4 ™ mark
- `haunt-app.tsx:413` shows `™`. The audit and owner notes say name clearance is pending. **Fix:** remove until cleared.

### L-5 Hard-coded copy
- "Good evening, Keeper" (`:465`) and "THE VEIL IS THIN TONIGHT" show at any hour. Minor, but misleading in a daytime demo. **Fix:** compute greeting from the profile timezone, or neutral copy.

### L-6 Docs
- `docs/PRODUCT-STATUS.md` still lists "Automated tests and CI" as not implemented (tests exist; CI does not) and says the initial sample commitments are stored (README: "The initial sample commitments are fictional demo data. They are stored in the browser"), but demo data now loads only on request. `.env.example` keeps `postgres:postgres` (task 8.4 open). README does not mention e2e/contrast scripts, the licence, or incomplete export.
- **Fix:** edit those lines.

### L-7 Typed amount through floats
- `draft.ts:98-99` uses `Number(text)` then `toMinor` (float multiply). Probe: `toMinor(8.575)` gives 857 (decimal reading is 858 half-up). Browser `step="0.01"` blocks three-decimal input in a normal form submit, so practical impact is small. **Fix:** parse the decimal string into minor units without floats.

### L-8 Past or multiple dates
- "Pay school fees on 3 January 2026" (today 13 Nov 2026) returns an exact date with no warning, confidence 0.95. "R1 500 on 25 Nov and R300 on 30 Nov" notes multiple amounts but not multiple dates. "Visit 2nd floor clinic" is read as a due date (flagged, not wrong). **Fix:** flag past explicit dates and multiple date matches.

## 5. Risks and missing features

- **R-1 Ended series (latent):** `oneOffs = commitments.filter(status === "completed")` (`haunt-app.tsx:229`) includes an ended series master and the occurrence record for the same last date, so it would appear twice in The Crypt. Restoring the master would put it active on a date that already has a history record, so completing it again is blocked. Probe at domain level: ending a series sets `status: "completed"` and keeps one occurrence. **Not reachable today** because the form has no end date and there is no import; it becomes a bug as soon as end dates are exposed. Add a test first.
- **R-2 Headers:** `next.config.ts` has no CSP, frame-ancestors, referrer or nosniff headers. No `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `fetch`, `console.*` or external URLs in `app/`, `components/`, `lib/` (grep returned none). XSS surface is small (React escaping; user text rendered as text). Add headers before a public deploy.
- **R-3 Reminders:** a reminder not planned before its time passes (for example created after the moment, or app closed through it and the reconcile window) is never created (`plan.ts` plans future moments only). Documented, and the UI says "in-app only"; keep it in the demo script. `closeNotifications` marks anything it listed as shown, even if the user never scrolled to it (acceptable).
- **R-4 Storage boundary:** `storedDataSchema` does not require `data.userId === key userId` nor each item's `userId`. Probe: a blob under key `u` containing `userId: "OTHER"` loads as "loaded"; `list("u")` filters it out (0 items), so no cross-user leak, but `save` would then persist the foreign item alongside. Today there is only the fixed `"local"` user. Add a refine when a second user exists.
- **R-5 Review is advisory:** `canSave` needs only a title and a date (`haunt-app.tsx`, modal). A user can press "Confirm" while CHECK THIS markers remain. Nothing is saved without that click, and the markers are visible, so the requirement "confirm before commit" is met; a stricter requirement (acknowledge each flag) is not.
- **R-6 Test quality:** Domain tests are real: property tests for recurrence, DST, idempotent reminders (I saw no vacuous asserts; one `toBeDefined` at `tests/capture.test.ts:152`). Gaps: no React/component tests, so H-1, H-2, L-1, L-2 and the Crypt duplication passed. Weak e2e assertions: recurring completion passes if the row text contains "Dec" or "Nov" anywhere (`smoke.mjs`, steps "completing a recurring item" and "latest completion can be undone"); delete-all passes with leftover keys; sound step selects switches by index; no step checks export contents; the row-menu step tests hit-testing only. A failing implementation of the archive flow, export, or switch names would still pass.
- **R-7 Kiro usage log:** entries claim "Kiro IDE agent session (Vibe)" with evidence of docs and tests, which I cannot verify from the repo. The log correctly says the spec task runner, hooks and custom agents were not used. One hook (`post-task-verify`) and three agents are configuration only. Keep the "Not yet used" list; do not describe hooks or agents as active in the write-up. The three specs `core-experience` and `visual-atmosphere` remain; `visual-atmosphere` is marked superseded, `core-experience` is not mentioned in the audit as folded.
- **R-8 Assets:** the font licence texts are not in the repo (register says so). Icon provenance (`public/haunt-icon.svg`, `app/icon.svg`) unconfirmed. The manifest has one SVG icon with `purpose: "any maskable"`; no service worker, so "installable" must not be claimed. Fonts come from Google at build time; the e2e step proves no runtime request to Google.

## 6. Checked and fine

- **Date-only handling:** domain uses `DateOnly` strings, `todayIn(timezone)`, UTC arithmetic helpers. Components do not use browser-local `Date` for domain decisions. `new Date()` appears only for timestamps and the clock. Migration converts via the profile timezone and says times were dropped.
- **Money:** stored as integer minor units with currency required; totals grouped per currency (`sumByCurrency`); the "UPCOMING TOTAL" card shows one amount per currency and labels them as entered amounts. No cross-currency summing found.
- **Recurrence:** month-end clamp, leap year, anchor-based generation, idempotent ids, DST conversion: tests plus my probe agree. `SAFETY_LIMIT` (20,000) would silently end an extremely old daily series; years above 2200 would throw in `makeDateOnly` (edge, not reachable by normal use).
- **Reminder honesty:** states are scheduled/due/shown/snoozed/dismissed/cancelled. No "sent" or "delivered" in UI copy. The button "Send test reminder" is labelled TEST and shows "No commitment is involved". Reminders are cancelled for completed, archived, deleted or re-dated items (`reconcile.ts`). Stored reminders hold ids and dates only.
- **Capture honesty:** the review banner says "Read by the built-in rule-based reader (not AI)"; the `llm` branch label is unreachable (no provider). Nothing saves before Confirm (e2e proves it). Unclear dates stay empty and block saving. Fixed audit defects ("for 3 weeks", the 31st, bare "the 25th") hold in my probe ("Pay rent on the 31st every month" gives 30 Nov, flagged, day 31 kept).
- **Sound:** AudioContext is created only after a pointer/keyboard gesture and only with a toggle on (code `useHauntSound`; e2e counted 0 contexts, then 1). Defaults off. Gain ceiling in `lib/audio/levels.ts`. I did not listen to it.
- **Reduced motion:** `@media (prefers-reduced-motion)` plus `data-motion` override exist (`globals.css` around `:308-312`); e2e verifies both. Dissolve and seal are skipped under reduced motion.
- **Mobile:** no horizontal overflow at 390px on five views; no targets under 24px (probe and script).
- **Privacy:** no network calls, no logging, no secrets in the repo (grep: only placeholders and docs). `.gitignore` does not ignore `.kiro` and `.kiro` is tracked. Footnote "Nothing is sent anywhere" is true for the code I read.

## 8. Release-readiness verdict

**Not ready for submission.** The core is sound and honest, and all automated checks pass, but these block release:

1. H-3: add a LICENSE (owner decision).
2. H-1: archived items disappear; the toast says history is kept.
3. H-2: unnamed sound switches.
4. M-1 and M-2: delete-all leaves data behind, and export is incomplete. Both are privacy/trust items the steering names.
5. Deployment, public repo and video do not exist yet (release-and-demo spec tasks 9.5 to 9.9 open).

Strongly recommended before demo: M-3, M-4 (parser trust), M-5 (legibility), L-1, L-4, L-6. M-6, M-7, M-8 and R-1 can be scheduled but must not be hidden in the write-up.
